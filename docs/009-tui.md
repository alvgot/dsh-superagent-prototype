# 009 Terminal

The panel of [005 Panel](005-panel.md) assumes a browser. When the operator works in a terminal, the same
agent runs behind a terminal surface instead: a plugin in the profile they already use, talking to the
service over loopback. Nothing about the service changes; only the place the person looks.

This document builds on [000 Philosophy](000-philosophy.md) through [008 Cookbook](008-cookbook.md).

## Two profiles, one service

| Profile | Role |
| --- | --- |
| `superagent` | Runs the service: the bundle plus the web host, `--no-open`, management API on `127.0.0.1:3082` |
| `dsh-tui` | Where the person works; loads the `dsh-superagent-tui` plugin |

The profiles stay separate for the reasons in [006 Deployment](006-deployment.md): the bundle rewrites
process-wide PATH and git settings for its `gh` wrapper, and a profile owns its plugin tree. In the
terminal setup the service never serves a page, and the person never opens one.

```text
dsh-tui process ──HTTP──▶ 127.0.0.1:3082 /orchestrator/api/
   (the plugin)                  (the superagent profile)
```

Every request carries the `x-orchestrator-request` header the management API requires; the plugin never
reads the orchestrator's files or credentials, and no request leaves the machine.

## What the person gets

- **A side panel** in the DeepSeek Harness TUI sidebar, named **Superagent**, with the three questions of
  [005 Panel](005-panel.md): tickets that need a person, system health, and the detail of one ticket. `tab`
  switches between tickets, overview and settings; `enter` opens a ticket; `p` pauses or resumes the
  executor, `r` retries, `s` stops, `c` re-runs setup checks.
- **One footer cell**, refreshed every ten seconds: `sa 0/3` (workers running), `sa 1/3+2 !` (queued, one
  waiting for a person), `sa setup`, `sa paused`, `sa off`. Hovering shows the detail; clicking opens the
  panel.
- **Two shortcuts**, `alt+a` and `ctrl+shift+s`, that open the panel. `alt+s` is the TUI's own *star the
  repository* action, so the plugin does not use it.

The plugin is plain ESM JavaScript with no dependencies, so installing it needs no build step.

## Installing

```sh
dsh plugin --profile dsh-tui add "link:<checkout>/tui"
```

Then restart the TUI profile: a running process keeps the plugin modules it loaded at start. The bundle
patch inserts one row:

```yaml
- id: superagent-tui
  name: dsh-superagent-tui
  config:
    url: http://127.0.0.1:3082    # the service the superagent profile serves
    pollMs: 5000                  # panel refresh; the footer uses 10 s
```

`tui/README.md` covers the files and the panel's own contract.

## Things that bite

- **A profile plugin is composed before the host registers its services.** Reading `tuiPanels`,
  `tuiStatus` or `tuiShortcuts` with `ctx.get` at apply time finds nothing on a cold start, and the
  plugin silently does nothing. The plugin awaits each seam with `ctx.inject`, which also keeps the panel,
  the footer and the shortcuts independent: a host without one of them keeps the other two.
- **A reserved shortcut is refused silently.** The host returns a no-op disposer for a combo it owns, so
  the plugin checks `shortcuts.list()` and logs a warning instead of assuming success.
- **The footer field only renders while a session is on screen.** On the welcome screen it is absent, not
  broken.
- **The side panel is experimental.** It is not selectable or copyable, and the compact row is not mounted
  yet; the full panel is.

## Verified end to end

A copy fix on `alvgot/superagent-sandbox`, performed in a terminal-only setup:

| Time | Event |
| --- | --- |
| 17:36:27 | the operator comments `@dsh-superagent-alv fix the typo …` on an issue |
| 17:37:22 | the ticket exists, stage `working` (one poll cycle) |
| 17:37:58 | a pull request from branch `agent/fix-greeting-typo-…`, commit authored by the agent account |
| 17:43 | the operator merges |
| 17:44 | the ticket ends |

The panel showed the ticket in the `person` stage while it waited for the merge, and `sa 0/3` afterwards.
